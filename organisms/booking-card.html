Overview · 概览

预约商卡由两个维度共同决定：业务类型（常规预约 / 荷兰拍 / 荷兰拍预约态 / Happy Hour）与售卖状态（未预约 / 抢购中 / 已结束）。 两个维度共同驱动价格、时间、库存与 CTA。

03

Types · 类型

Figma 母组件包含四种业务类型；每种类型再叠加未预约、抢购中、已结束三个售卖状态。

Reservation · 常规预约
库存、开售时间、价格与 Notify 操作。
Dutch Auctions · 荷兰拍
当前价、RRP 参考价与下一次降价时间。
Dutch Auction Reserved · 荷兰拍预约态
荷兰拍开始前的预约状态，强调库存和开始时间。
Happy Hour · 月黑
紫蓝价格条与克制的业务色；未预约、抢购中、结束状态分别使用绿色、红色与灰色操作。
04

Data Contract · 数据契约

Booking 卡在 Product 基础上增加 state / startsAt / endsAt 三字段；所有可见文案均来自 Figma 原子组件。 业务标签由 type 派生，时间、价格与 CTA 由 state 驱动，两者不能混用。

06

When to Use · 何时使用

Booking 与普通商卡的区分是"时间紧迫感"——常态在售的商品不该穿 ribbon 装成秒杀， 反过来真正限时的商品也不能只用普通商卡承载。

选 Booking / Auction 当
  • 商品有明确开售 / 结束时间点
  • 用户需要提前"注册"或参与竞价
  • 倒计时是核心决策信号
  • 需要展示库存紧张感作为稀缺信号
  • 业务类型与三种售卖状态需要分别建模
选 Vertical / Horizontal 当
  • 商品常态在售
  • 无倒计时紧迫感
  • 用户可以随时下单
  • 更看重品牌 · 卖家 · 履约状态
  • 促销靠 highlight / promotion 表达（不锁时间）
DO
  • 业务标签只由 type 决定，不能被售卖状态覆盖
  • 未预约显示开始时间，抢购中显示倒计时，结束态隐藏时间
  • 库存文案使用 Figma Stock 原子的 Only 12 items left / Out of stock；预约量使用 999+ reservations，不自行改写
  • 倒计时精度到秒 · JS 层做客户端滚动 · 不要 fetch 更新
  • 荷兰拍必配"下一档 £YYY"提示 · 让用户知道降价节奏
DON'T
  • 别在普通推荐位塞 Booking · 会造成"处处都是秒杀"的通胀
  • 别把 ribbon 颜色写死 · 一定要 state 派生
  • 别为 Ended 状态保留 CTA 主色 · 一律 ghost + dim
  • 别让倒计时到 0 后卡片还挂在楼层 · 应立刻切 state=ended
  • 别在 Auction 卡里显示 originalPrice 划线价 · 拍卖没有 RRP 概念
